# 网易云红心歌单分类

把网易云歌单按**单个分类维度**整理成你指定的目标歌单。

可以从「我喜欢的音乐」或其他已有歌单导入；分类后逐类选择已有目标歌单，或新建歌单。已有目标只追加歌曲、跳过重复项，不会删除原有内容。

## 0.2.0：按歌手分类

这是基于 [nill-sy/netease-playlist-organizer](https://github.com/nill-sy/netease-playlist-organizer) 的功能分支。

- 直接按网易云歌曲资料中的完整歌手名称分组，**无需 AI、模型 API Key 或模型接口权限**。
- 合唱同时归入每位歌手；去除空名称和重复名称，没有有效歌手信息的歌曲留在「未分类」。
- 每位歌手默认对应同名歌单；预览时可改选已有歌单，例如将「周杰伦」对应到已有的「Jay」。
- 歌手名完整保留，不因超过 12 字而截断或调用 AI。新安装默认选择歌手，升级后保留已保存的维度选择。
- 手动调整一项歌手归属时保留此歌其他归属；合并歌手分类和导入同一目标时都会去重。
- 重新计算导入计划时刷新目标列表；新建后记录目标 ID，导入失败即停止，重新计算后再试。
- 歌曲明细展开后才渲染，避免大歌单在打开预览时同时生成大量下拉选项。

按网易云返回的名称分组，不自动推断艺人别名，也不区分同名艺人。原有曲风、情绪、语种和年代功能仍保留。

已打包的扩展请参阅 [安装说明](INSTALL.md)。**本功能分支未运行功能测试，真实账号接口兼容性未测试。**

## 为什么做成浏览器扩展

| 方案 | 结论 |
| --- | --- |
| 纯前端网站 | ❌ 网易云接口**不返回 CORS 头，也不支持 JSONP**（已实测），浏览器读不到响应，技术上不可行 |
| 本地 Web App | 🔶 可行，但要自己实现扫码登录 + 会话持久化 + 应对 `code 8821` 风控 |
| **浏览器扩展** | ✅ **复用浏览器里已有的登录态，完全不需要做登录** |
| iOS App | ❌ 必须装 Xcode、自签后**每 7 天续签**，且手机端要自己实现 `eapi` 加密与设备头 |

扩展可以复用已有登录状态，省去单独实现登录的步骤；批量写入仍可能受到网易云限流或风控。
使用范围是桌面 Chrome / Edge，整理任务期间需保留网易云标签页。

## 架构

```text
页面内浮窗（扩展 panel.html iframe，收起时仍保持运行）
    │  chrome.tabs.sendMessage
    ▼
content script（运行在 music.163.com 里）
    │  fetch —— 真正的同源请求
    ▼
网易云 /api/*
```

两个关键设计：

1. **HTTP 全部走 content script**。它跑在 `music.163.com` 同源上下文里，cookie 和
   `__csrf` 天然可用，完全绕开 CORS 和 SameSite 问题。
2. **分类任务跑在页面内的扩展浮窗 iframe**，不放 service worker —— MV3 的后台 worker 会被回收。浮窗最小化不会中断任务；关闭或刷新网易云标签页会中断任务。

## 安装

```bash
npm install
npm run build
```

然后打开 Chrome：

1. 访问 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本项目的 **`dist/`** 目录

## 使用

1. 先打开并登录 `https://music.163.com`（**保持这个标签页开着**，插件靠它发请求）
2. 在网易云标签页点扩展图标，出现 48px 浮球；点浮球展开约 380×560 的可拖动卡片，收起后任务继续
3. 按流程走：检测登录 → 选来源歌单 → 读取歌曲 → 选择分类维度 → 分类 → 逐类选择已有/新建目标歌单 → 预览 → 确认导入。选择「歌手」时不用配置模型。

仅使用需要模型的分类或命名功能时才需配置模型，可使用 OpenAI 兼容接口（DeepSeek / GLM / 通义 等）。按歌手分类无需这些配置。
API Key 保存在 `chrome.storage.local`，调用分类时会随请求发送到你配置的模型服务商；歌曲名、歌手和专辑信息也会发送给该服务商。首次调用时浏览器会申请该接口域名的访问权限。

## 设计要点

### 安全导入

分类预览后，可以为每个类目选择一个已有目标歌单，或新建歌单并自定义名称。多个类目也可以有意映射到同一个目标。

- 已有歌单只**追加**分类出的歌曲，不会删除目标中的其他歌曲
- 目标中已存在的歌曲会自动跳过
- 同名已有歌单默认建议复用；也可以在预览中改选目标
- 未分类歌曲留在预览中，可手动归类；未归类时不会导入

预览先展示各目标的计划和新增数量，确认后才写入账号。

### 简化分类维度

主界面突出「歌手、曲风、情绪、语种」；「年代」收在「更多维度」中。每次只运行一个维度。

曲风分类默认上限为 3 类，可调到 2–8 类。首次运行时，AI 从当前歌单均匀抽取最多 120 首作为样本，生成类别名称和判定范围；随后固定这套规则，对全歌单分批分类。类别方案按来源歌单、模型和上限保存在本地，重复整理时复用；需要适应歌单变化时，可勾选重新分析。AI 可以少于上限，不会为凑数强拆类别。

### 歌单命名风格

提供「简洁直白」（默认）、「日式文学」、「复古唱片」、「电影感 / 氛围感」和自定义描述。建议名称不超过 12 字；风格只影响新歌单名称建议，不影响分类结果。名称建议单独缓存，切换风格时只刷新名称，不重做分类；预览中仍可逐个修改。已有歌单名称不会被改动。

| 维度 | 做法 |
| --- | --- |
| 歌手 | 按歌曲资料中的完整歌手名单分组，合唱分别归入每位歌手，不调用模型 |
| 年代 | 直接用 `publishTime` 计算，不消耗分类模型 token |
| 语种 | Unicode 区间 + 歌手名预判，再交给模型复核 |
| 曲风 / 情绪 | 依赖模型根据歌名、歌手和专辑推断，准确率有上限 |

### 结果缓存

分类结果缓存键包含模型服务地址、模型名及类别定义；歌单名建议按命名风格单独缓存。更换模型或重新生成分类规则后会隔离旧分类缓存；只切换命名风格不会导致歌曲重新分类。

## 已实测的接口事实

写这个项目前逐个验证过，避免基于猜测开发：

- ✅ `/api/w/nuser/account/get` —— 登录态检测，未登录返回 `account: null`
- ✅ `/api/user/playlist` —— 「我喜欢的音乐」用 **`specialType === 5`** 识别
- ✅ `/api/v6/playlist/detail?id=X&n=0` —— `tracks` 为空但 **`trackIds` 是完整的**
  （实测 965 首的歌单返回 965 个 id），这是最省流量的取 ID 方式
- ✅ `/api/v3/song/detail`（POST `c=[{id},...]`）—— 批量取元数据，**每批 100 首**稳定（200 会被截断）
- ✅ `/api/playlist/create`、`/api/playlist/manipulate/tracks` —— 存在，未登录返回 301 而非 404
- ✅ 大部分 `/api/` 是**明文接口，不需要 weapi 加密**（参考项目里自研的 RSA + 双层 AES 其实用不上）
- ❌ `/api/song/tags` —— **已下线（404）**。所以「按网易云标签做规则分类」这条路是死的
- ❌ `/api/playlist/track/all`、`/api/song/url/v1` —— 也已 404，说明网易在持续下线老接口

## 已知限制与风险

- **曲风/情绪的准确率有天花板**：网易不提供曲风标签，只能靠歌名/歌手/专辑名让模型推断
- **风控**：批量建歌单和加歌是高频写操作，已内置 220ms 最小请求间隔；每次仅运行一个分类维度
- **接口会变**：网易在持续下线老接口，将来可能需要跟着调整
- 「我喜欢的音乐」本身有 **10000 首上限**
- 浮窗和分类任务依赖 `music.163.com` 标签页保持打开；关闭或刷新该标签页会中断当前任务

```bash
npm run dev        # 热更新开发
npm run typecheck  # 类型检查
npm run selftest   # 规则与模拟导入自测；本次交付未运行

```

`tests/selftest.ts` 覆盖歌手多归属、手动调整、旧设置兼容、无 Key 的歌手分类与命名、模拟导入去重及失败重算，以及原有年代、语种、曲风抽样、缓存、JSON 容错和目标选择。
这些函数不依赖网络但会静默影响全部结果，所以用断言盯住 —— 它已经抓到过一个真实 bug
（1970 年前的负数时间戳被误判为无效）。
